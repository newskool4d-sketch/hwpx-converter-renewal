## 의존성과 설치 방식

- 프로젝트 전용 `deps/kordoc`: kordoc **4.21.30**, pdfjs-dist **4.10.38**, lockfile 고정.
- Node.js **v24.14.1** 사용. EXE에도 실행 파일 옆 `deps/kordoc`와 기존 Node.js 20 이상이 필요하다.
- 기존 `mcp-servers/kordoc` **4.21.19**와 MCP 설정은 변경하지 않았다.
- lifecycle script·선택 의존성 제외 설치. 문서는 로컬 Buffer로 읽고 새 연결의 네트워크·자식 명령 실행을 차단했다.
- npm audit의 이번 조회 결과 취약점 **0건**. 이는 모든 취약점의 부재를 보증하지 않는다. [설치 전 심사](kordoc-security-review.md)에 조건과 원문 근거를 기록했다.

초기 COM 세션 재사용 검사에서는 표 샘플의 선행 공백과 PDF 차이가 나왔다. 해당 결과를 보존하고, 변경 전·후를 각각 새 한컴 세션으로 실행해 동일 조건의 본문·셀·PDF 픽셀 일치를 확인했다. 모든 실제 문서에 대한 무회귀 보증으로 확대하지 않는다.

PDF 실COM 검사에서 `Pixmap.samples` 전체 복사가 매 픽셀마다 반복되는 기존 검사 병목을 고쳤다. 비교하는 픽셀 값·오차 기준은 동일하다. 진단용 faulthandler 실행에서 COM 종료 시 RPC 진단 메시지가 기록됐으나 테스트 판정은 성공이었다. 이후 일반 실행의 최종 399개 통합 검사에서도 실제 한컴 PDF 항목이 통과했다.

## 최종 설치·취소 검증

실제 정상 변환과 취소 모두 **PASS**. 취소 신호 이후 **0.248초** 안에 반환했고 출력 파일을 만들지 않았으며 원본 SHA-256은 같았다. 정상·취소 모두 즉시 및 1초 뒤 한글 잔여 프로세스 **0개**였다. 증거는 `out/native-success-final.json`, `out/native-cancel-final.json`이다.

초기 취소 시험의 빈 한글 창 잔류는 보존된 `out/native-cancel-summary.json`에 기록했다. 이를 해결하기 위해 협조적 취소 신호와 최대 2초 정상 종료 대기를 추가하고 재검증했다. COM 호출 자체가 응답하지 않는 경우까지 한글 종료를 보증하지는 않는다. 제한 시간을 지키기 위해 앱의 Python 작업만 종료하며 사용자 한글 프로세스를 일괄 종료하지 않는다.

설치한 실행 파일은 프로젝트의 기존 경로 **`dist/anyway_to_hwpx_gui.exe`**(75,239,539바이트, `2026.10.04+dev`)다. 기존 실행 파일은 **`out/backups/20261013-pre-kordoc/anyway_to_hwpx_gui.exe`**에 원본과 SHA-256이 동일한 백업으로 보존했다. 복원하려면 앱을 종료한 뒤 백업 EXE를 기존 경로에 복사하면 된다. 새 `dist/deps/kordoc`는 기존 실행 파일이 사용하지 않는다.

- 설치 EXE SHA-256: `32E5880E3E65FF58948B438274EB5B95EB37125D25694F8B1AED6AF98A463C1F`
- 기존 EXE·백업 SHA-256: `74F689B36C4F52AACADF446D04F1AE1E4E481DD64B64977DF808B591620E43C2`
- 설치 기록: `out/installation-final.json`, 백업 기록: `out/installation-backup.json`.
- 최종 후보의 frozen 작업 프로세스 **PASS**: 외부 소스 없이 새 모듈 4개를 번들 안에서 불러왔고, EXE 인접 kordoc **4.21.30** 진단·HWPX 읽기 성공, 입력 해시 불변, 종료 코드 0, 잔여 프로세스·임시 번들 없음. `out/frozen-spawn-smoke.json`에 기록했다.

설치된 경로에서도 같은 번들·문서 진단 검사가 **PASS**였다(16.267초). 인접 패키지 선택, 진단·읽기 성공, 입력·EXE 해시 불변, 종료 코드 0을 `out/installed-frozen-smoke.json`에 기록했다. EXE를 다른 폴더로 옮길 때 문서 도구를 사용하려면 `deps/kordoc` 폴더도 함께 옮겨야 한다.
